# Physical-device acceptance still required

Use a dedicated authorised test directory and the normal Mac account’s Remote Login service. Never rotate the real Mac’s host keys for testing. The independent OpenSSH fixture covers changed trust without doing that.

1. In Xcode choose your signing team, run on an iPhone with iOS 27, and add the dedicated app key’s public key to the Mac account.
2. Enable existing Tailscale on both devices. On iPhone disable Wi-Fi and use cellular. Open a saved favourite directly, verify the host fingerprint, browse, and open a real agent Markdown report. Record the route with `scripts/test-cellular-tailscale.py` ([procedure](REAL_SERVER_ACCEPTANCE.md#cellular-and-tailscale-evidence)). On the iPad, its own cellular data reached the Mac through a Tailscale relay, and the journey and an interrupted refresh passed ([18 November iPad follow-up](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-follow-up)).
3. Scroll the folder first; open/back from a report and confirm the folder position. Change the report in the approved Mac test directory, refresh in the reader, and confirm new content. Interrupt the network during another refresh and confirm the previous copy remains clearly labelled; this interruption passed over cellular ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)).
4. Background/foreground SSH teardown and fresh document read passed on hardware ([evidence](DEVICE_PERMISSIONS_LIFECYCLE.md)). Encrypted-key unlock, cancel/swipe-dismiss, no passphrase persistence, keychain availability after locking, and private-key export also passed ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)). Changing only a disposable fixture server's key blocked the iPad before account authentication ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)). On the iPad, an encrypted key imported, its prompt could be cancelled or swiped away, and the passphrase was asked again after Disconnect, backgrounding and locking ([18 November iPad follow-up](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-follow-up)).
5. Local Wi-Fi denial, useful failure state, Settings recovery, and retry passed on hardware ([evidence](DEVICE_PERMISSIONS_LIFECYCLE.md)). A timeout must not be described as a proven Tailscale/sleep/firewall diagnosis.
6. Check light/dark appearance, accessibility Dynamic Type, VoiceOver reading/focus, Reduce Motion and Reduce Transparency. Long-press to select/copy rendered text and source. Pan a wide code block/table horizontally without widening the overall document. These passed on the iPhone ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)) and the iPad ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)).
7. Profile a 1,000-entry folder and the generated 191,002-byte report on the device using Instruments SwiftUI / Animation Hitches. Record cold/warm timings, main-thread hitches and memory; do not interpret Simulator/loopback times as cellular performance. On the iPad the Animation Hitches and Allocations templates recorded; the SwiftUI template saved no CPU or hitch data there. Opening either stalled the main thread for about 90 ms; scrolling the folder to its end dropped runs of frames while SwiftUI's List located new cells, an open finding, and the report dropped single frames ([18 November iPad follow-up](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-follow-up)).
8. In the authorised test directory, choose **Contents** and search a phrase inside a UTF-8 file whose name does not contain it. Check the source-line snippet, open/back retention, refresh after editing that file, hidden-file policy, cancellation on background/disconnect, and the partial-results explanation at a read limit. On iPad, verify the folder's search controls and snippets with the reader beside them, in a narrow window, with accessibility text sizes and VoiceOver. This journey passed on the iPad, including those iPad checks ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)); it has not run on the iPhone.

9. Save an individual file with **Keep Offline**, disconnect, relaunch and open it from **Offline Files** without network access. Verify its saved date, text/media controls and Share Original bytes. Use Find and Headings in a saved Markdown copy, zoom a saved image, and confirm a saved text or PDF copy reopens at its position after relaunch. Update an authorized fixture, choose **Update Offline Copy**, and interrupt a later update: the last committed copy must remain readable. Remove only the local copy and verify the server original remains. Check Complete file protection while locked using a controlled device test; simulator permissions are not proof. Repeat the library flow in iPad regular and compact windows and with VoiceOver. On the iPhone, whose build then had no offline Find or Headings, the saved date, Share Original bytes, Update Offline Copy, an interrupted update and removal passed; the interrupted update gave no explanation until its time limit ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)). On the iPad the saved date, Find, Headings, image zoom, a plain-text position after relaunch, Share Original bytes, Update Offline Copy and removal passed in a regular window, and the saved files could not be copied out of the app's container while the iPad was locked but could once it was unlocked ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)). A saved PDF's position after relaunch, an interrupted update (explained after the three-minute offline transfer limit, the saved bytes unchanged), a narrow window and VoiceOver in the offline library then passed on the iPad too ([18 November iPad follow-up](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-follow-up)).
10. Choose **Keep Folder Offline** for a small controlled tree containing nested and empty directories, hidden files and symbolic links. Check the hidden-file choice and skipped-link count. Disconnect and browse the complete saved hierarchy; preview/share an original, background and relaunch. Change/add/delete remote members and choose **Update Offline Folder**; the replacement must include those changes. Interrupt an update or make a member unreadable and verify the old snapshot remains complete. Remove a saved folder while another window updates it and confirm it never reappears; independently saved files and overlapping snapshots must remain. Exercise a storage/depth limit and verify no partial folder is published. All but the multiwindow removal passed on the iPhone ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)); the multiwindow removal passed on the iPad ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)). The storage and depth limits were not repeated there.
11. While disconnected, follow relative Markdown links between saved sibling, nested and parent documents, plus same-document and linked heading fragments. Back must retain the source reading position. A missing/hidden/skipped target, unsupported type, query or path leaving the snapshot must explain the failure and retain the reader. Overlapping snapshots and individually saved copies must not substitute for folder members. Repeat between individual copies from the same saved connection route; other accounts/routes must not match. Update/remove an open source in another window and verify its file links require reopening. No file-link tap should reconnect or download missing content. The single-window cases passed on the iPhone; repeated link hops could exhaust the four offline preview leases ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)). On the iPad the link cases and eight hops in a row passed ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)); the other-window and route cases were not checked.

12. In a long standalone HTML fixture, scroll into prose and a tall visual/table block, then rotate the iPhone, change text size and resize an iPad window. Reopening the unchanged file and switching Rendered/Source must retain their independent locations; changed content starts at the top. Interrupt restoration with touch, keyboard and VoiceOver scrolling, then background/foreground and navigate Back. Confirm document scripts/resources remain blocked and profile inactive HTML reader memory. These passed on the iPad ([18 November iPad evidence](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-session)), apart from profiling inactive reader memory; the iPhone rotation has not been checked.

13. With **Include PDF Text** enabled, search a phrase on a later page of a multi-page PDF in the authorised test directory. The live result and a saved-index result must each open at that page. Scroll to another page and mid-page, go back, reopen, relaunch and rotate: the page and approximate position must return. Replace the PDF on the server, refresh, and confirm it opens at the top. Passed on the iPhone ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)).

Managed downloads request iOS continued background processing. Verify an active transfer in the background, system cancellation, resource expiration, lock, relaunch and explicit Disconnect; interrupted work must expose Retry and never report partial bytes as complete. Retry should continue from the kept bytes (the Downloads row shows how much is kept) and the finished file must match the server's SHA-256; replace the file on the server between attempts and Retry must start again. Resuming after Airplane Mode and a force quit, and restarting a replaced file, passed on the iPhone ([2 November evidence](REAL_SERVER_ACCEPTANCE.md#2-november-2026-download-resume)). On the iPad, over cellular, a transfer continued in another app with a Live Activity and while locked; cancelling it from the Live Activity, Disconnect and a force quit each kept its bytes, Retry continued, and the file matched the server's SHA-256 ([18 November iPad follow-up](REAL_SERVER_ACCEPTANCE.md#18-november-2026-ipad-follow-up)). iOS ending a background transfer by itself has not been seen. Queued work must not start a new SSH authentication in the background. iOS may stop continued processing, and transfers do not survive app termination. Complete this journey before describing the preview as physically verified. On the iPhone everything but forced resource expiration passed, and Wi-Fi/cellular handoff did not interrupt a transfer; a transfer during network loss waited for the network to return instead of failing after 60 seconds ([31 October evidence](REAL_SERVER_ACCEPTANCE.md#31-october-2026-iphone-session)).
